## 1. Проект: что это и как устроено

«Тихолесье» — спокойная вертикальная прыгалка по мшистым кочкам ночного леса: один файл `index.html`, вся графика рисуется кодом на canvas, звук синтезируется. Автор — Андрей. Он играет на iPhone 16 Pro Max без интернета (например, на остановке), разрабатывает на ПК с Windows.

**Где живёт.** Публичный репозиторий `plush-reiko/tiholesye`, ветка `main`. GitHub Pages раздаёт корень репозитория. На айфоне игра стоит с экрана «Домой» и работает без сети через service worker.

| Файл | Что внутри |
| --- | --- |
| `index.html` | Вся игра, 432 КБ: разметка, CSS, шрифты в base64, весь JS |
| `sw.js` | Офлайн-кэш. Имя кэша (сейчас `tiholesye-6446bdcbce44`) = версия: новое имя — телефон скачает обновление |
| `manifest.webmanifest` | Имя, цвета и иконки приложения |
| `icon-180.png`, `icon-192.png`, `icon-512.png` | Иконки: герой на пне в ночном лесу |
| `Обновление-2026-11-19.md` | Журнал правки 19.11. Переедет в `ИСТОРИЯ.md` |

**Устройство `index.html`.** Строки 1–333: заголовок и CSS (шрифты — строки 5–10). Строки 334–540: разметка экранов и SVG-значки. Строки 541–3885: весь JS одной самовызывающейся функцией. Внутри семь разделов с заголовками `/* ===== Тихолесье · … ===== */`: core, звук (`Snd`), графика (`Art`), мир, отрисовка кадра, интерфейс (`UI`), запуск. Функции и строки — в Приложении А.

**Мир и правила**

- Ширина мира 400 единиц (`WW`), высота по экрану. В мире y растёт вверх, на экране вниз (`Y(y)`). 1 м счёта = 10 единиц. Физика идёт шагом 1/120 с.
- Пять зон по высоте: Грибная поляна с 0 м, Папоротниковая чаща с 600, Кристальные своды с 1 600, Лунные кроны с 3 000, Звёздная высь с 5 000 м (`ZONES`). Цвета между зонами перетекают (`zoneMix`).
- Платформы (`mkPlat`, `Art.plat`): `static` — кочка, `moving`/`vmove` — плавучая, `bouncy` — гриб-батут, `puff` — одноразовая, `fake` — призрачная, `phase` — мерцающий кристалл, `home` — вершина пня, `ground` — земля.
- Находки на кочках: одуванчик, комета, пузырь, фонарик, перо. Крылья — запасной прыжок в воздухе с зарядами и перезарядкой.
- Множитель ×1…×5 (`FLOW`, `setMult`) растёт за новые кочки подряд и умножает светлячков (валюту), а не метры.
- Монстр сейчас один — ворчун (`game.grumps`), с 900 м, вне дзена.
- Лавка: облики (`SKINS`, 14), следы (`TRAILS`, 8), усиления (`UPS`, 6). Задания (`MDEF`) и ранги (`RANKS`). Режимы «Забег» и «Дзен».

**Сохранение.** `localStorage` по ключу `tiholesye.save.v1`, JSON по схеме `freshSave()`. Любые данные идут через одну проверку `applySave()`. Код переноса — `TL1.` + base64 (`exportCode`/`importCode`), внутри поле `v: 1`.

**Отладка.** `window.__tl` отдаёт `game`, `P`, `run`, `save`, `Art`, `Snd`, `UI`, `startRun`, `update`, `render`, `genUpTo` и другое. На нём держатся автотесты и снимки. Оставь его и добавь туда всё новое.

**Исходники на ПК устарели.** В папке `D:\iphone_offline_game` лежат `src/` по частям, `build.mjs`, тесты, `CONTEXT.md`, `JOURNAL.md`, `TZ-REDESIGN-V4.md`. Правка 19.11 сделана прямо в `index.html` из GitHub, и исходники о ней не знают. С этого обновления источник правды — репозиторий. Если у тебя есть доступ к этой папке, перенеси из `JOURNAL.md` и `CONTEXT.md` полезное в `ИСТОРИЯ.md` и `CLAUDE.md`, но код бери только из репозитория.

## 3. Принципы и что нельзя ломать

Главное правило: игрок не должен даже задуматься, что игру нарисовал ИИ. Минимализм — это мало объектов и мало шума, а не бедные формы.

**Принципы**

1. **Нарисовано человеком.** Формы собраны из вручную расставленных точек, а не из кругов, эллипсов и звёзд. Асимметрия осознанная. У каждого существа свой характер.
2. **Стиль мира — «ночная аппликация».** Плоские заливки без градиентов. Объём — вторым тоном с жёсткой границей, не больше трёх тонов на деталь. Края чуть неровные, как вырезанные ножницами. Жёсткая тень, как под бумагой в интерфейсе.
3. **Минимализм без примитива.** Первая версия была перегружена, вторая — примитивна: сразу видно, что всё собрано из простейших фигур. Целимся между ними.
4. **Палитра мира.** Ночь: синий, голубой и фиолетовый с перевесом в синий. Светлячки (`#ffe3a0`) — единственный тёплый светящийся цвет леса. Облики могут быть тёплыми и контрастными (это герои), но «под луной» (раздел 10).
5. **Ничего из чужих игр.** Ни персонажей, ни названий, ни узнаваемых решений (как платформа с трещиной, разламывающаяся пополам из Doodle Jump).
6. **У каждого существа своё движение.** Одна и та же «пульсация» на всё — тоже штамп.

**ИИ-штампы, которых не должно быть нигде в игре**

- Одно «милое» лицо на всех: овальные глаза с двумя бликами и розовые овалы румянца.
- Четырёхлучевые «искры» и пятиконечные звёзды как украшение.
- Фигуры из идеальных кругов и полукругов: луна-диск, облака-полукруги, кроны-кружки, островки-треугольники.
- Зеркальная симметрия живых существ.
- Один и тот же блик слева сверху и тень-серп справа снизу у всего подряд.
- Свечение на всём, фиолетовые градиенты, полупрозрачные пятна вместо форм.
- Пастельная сиренево-голубая гамма у всех персонажей сразу.
- «База + шапка»: одно тело на всех, отличается только то, что надето сверху.

**Что нельзя ломать**

- **Прогресс игроков:** светлячки, рекорды, задания, ранги, улучшения, настройки. Код переноса из старой версии должен загружаться в новую (миграция — раздел 10).
- **Офлайн:** `sw.js` и список `FILES`. Имя кэша меняется при каждой выдаче (раздел 14).
- **Физика, генерация и сложность** остаются как есть, кроме правок про монстров и лист. Лес всегда проходим: рядом с одноразовой платформой всегда есть обычная кочка.
- **Игра:** управление (свайп, края, наклон, клавиатура), пауза, второе дыхание, дзен, рывок кометы, задания, звук и музыка.
- **Интерфейс «бумага и чернила»:** переменные `:root`, срезы `--cut-a/b/c`, шрифты Underdog и Alegreya Sans, значки в HUD (кроме значка кометы, раздел 11).
- **Особенности iPhone:** кольца таймеров рисуются SVG-линией (с `transform: scaleX` Safari оставлял полосы). Поле кода сохранения — шрифт не меньше 16 px и лечение окна после клавиатуры (`healViewport`, `afterKeyboard`). Отступы safe-area.
- **Скорость:** 60 кадров на iPhone. Спрайты кэшируются (`Art.plat`, `simple`, `glow`), статичные контуры строятся один раз. Режим «Экономно» (`LITE`) убирает свечение и тяжёлые слои: всё новое тяжёлое он тоже выключает. Лимит частиц `game.parts` — 440.

## 5. Подарок дня: кнопка и 100 светлячков

Подарок дня — 100 светлячков раз в календарный день (местное время). Забирается кнопкой в меню, сам больше не начисляется. Сейчас его выдаёт `UI.gift()` при каждом `showMenu()`.

**Логика**

- Константа `GIFT = 100` рядом с другими числами core.
- Поле `save.gift` остаётся и значит то же: ключ дня, когда подарок забран. Миграция не нужна.
- `giftReady() = save.gift !== dayKey()`. Автовыдачу из `showMenu` убери.
- Кнопка показывается, когда `giftReady()`. Проверяй при `showMenu`/`syncMenu` и при возврате в приложение (`visibilitychange`), чтобы после полуночи она появилась без перезапуска.
- Нажатие: `save.gift = dayKey()`, `save.coins += GIFT`, `save.totalCoins += GIFT`, `persist()`. Двойное нажатие не даёт двойной награды.
- «Сбросить прогресс» по-прежнему сохраняет отметку дня: сброс не даёт второй подарок.

**Вид и место**

- Кнопка в верхней строке меню `#menu .mtop`, слева; счётчик светлячков остаётся справа. Разметка: `<button id="bGift" class="btn small gift" type="button" hidden>Подарок леса<svg class="ic"><use href="#i-fly"/></svg>100</button>`. У `.mtop` — `justify-content: space-between`, у `.coins` в ней — `margin-left: auto`, чтобы счётчик не прыгал, когда кнопка скрыта.
- Стиль — уже есть `.btn.small` (тёмная бумага с жёсткой тенью). Чтобы её замечали, кнопка раз в 2,4 с чуть покачивается (поворот ±1,5°, как бумажка на сквозняке). При `prefers-reduced-motion` без качания. Свечения нет.
- На низких экранах кнопка не должна наезжать на название игры: проверь снимками при высоте окна 700 и 956.
- Кнопка есть только в меню. На экране итогов её нет.

**Отклик на нажатие**

- Новый звук `Snd.fx.gift`: три мягкие восходящие ноты из той же пентатоники (чуть теплее и длиннее, чем `buy`).
- Из кнопки к счётчику пролетают 6–8 маленьких значков светлячка (`#i-fly`, цвет `--firefly`) по слегка разным дугам, 0,5–0,8 с, с задержкой между ними. Это обычные DOM-элементы над сценой с Web Animations; после полёта они удаляются.
- Число в счётчике `#mCoins` набегает от старого до нового за 0,6 с, счётчик коротко увеличивается, как в HUD.
- Кнопка исчезает за 0,2 с. Тост `toast('Подарок леса', 100)` в том же виде, что сейчас.
- При `prefers-reduced-motion` светлячки не летят, число меняется сразу.

## 6. Светлячки без стаек

Светлячки в лесу снова одиночные огоньки при любом множителе. Множитель показывают только надпись «×N» у счётчика (`#hMult`, уже есть) и сам счётчик, который прибавляет по N.

- **`drawCoins`:** убери всю логику стаек (`m`, `n`, `tail`, `R`, `spin`, спутники большого светлячка). Обычный светлячок = ореол радиусом 12 с мерцанием и точка радиусом 2,6, как до 19.11. Большой светлячок — `Art.firefly` без спутников. Размер ореола от множителя больше не зависит.
- **`game.swarm`** удали вместе с его расчётом в `update()`.
- **Поимка:** вспышка из 3 искр `'g'` у обычного (не `1 + mult`), 7 у большого. Надпись `+N` остаётся только у большого светлячка и у ворчунов.
- **HUD:** при каждой поимке при ×2 и выше надпись `#hMult` вздрагивает вместе со счётчиком: масштаб 1,18, 200 мс. Так видна связь: поймал одного — счётчик прибавил N.
- **Подсказка при первом ×2** (флаг `save.multTip` остаётся): «×2 — теперь каждый пойманный светлячок считается за двух. Новые кочки подряд разгонят множитель до ×5».
- **Третья подсказка обучения** (`tutorial`): «Прыгай на новые кочки подряд — растёт множитель светлячков, до ×5. Снова на ту же кочку — он падает».
- **Памятка:** вместо картинки «одиночка → стайка» нарисуй кусочек счётчика «×3, значок светлячка, 12» теми же цветами и шрифтами, что в HUD. Текст — раздел 12.

## 7. Призрачная платформа: пунктирный «стадион»

Меняется только форма типа `fake`: вместо силуэта кочки — пунктирный «стадион», прямоугольник с полукруглыми концами. Поведение, звук и таяние остаются как сейчас. Андрей просил максимально простую фигуру, поэтому здесь чистая геометрия уместна: это знак «здесь ничего нет», а не живой предмет.

**Форма (`Art.ghost`)**

- Начало координат, как у всех платформ: (0, 0) — точка приземления, верх по центру, y растёт вниз.
- Ширина `w + 4`, верхняя сторона на y = −1, нижняя на y = 12. Концы — полукруги радиусом 6,5. Верх и низ параллельны.
- Заливка `#dde3ff` с прозрачностью 0,10.
- Пунктир по контуру: `#e8ecff`, прозрачность 0,9, толщина 1,3, круглые концы. Штрихи как от руки: длина 3,0–4,2, промежутки 2,2–3,0. Они заданы семенем спрайта и не меняются от кадра к кадру. Рисуй отрезками вдоль контура, не через `setLineDash` с одним шагом.
- Внутри 2–3 крошечные точки «морока» (белые, радиус 0,5–0,8, прозрачность 0,45–0,75).
- Убрать: бугристый верх «мха», внутренний пунктир мха и камня, клин камня, струйки тумана снизу.

**Что остаётся как есть:** «дыхание» и лёгкое покачивание в `drawPlats`, таяние от любого касания (`vanish`, проверка в `stepWorld`), звук `vanish`, туман при таянии, ширина из генерации. В памятке поправь `LEG_MID.fake` на центр новой формы (около 5,5). Название «Призрачная кочка» остаётся, текст памятки — раздел 12.

## 8. Одноразовая платформа: сухой лист

Тип `puff` становится сухим листом: держит один прыжок, потом срывается и, покачиваясь, планирует вниз. Никаких трещин, половинок и щепок: именно они делали ветку копией платформы из Doodle Jump. Ключ типа `puff` и ключ задания `puffs` в сохранении не меняются.

**Удалить:** `Art.twig`, `Art.crackClip`, `TWIG_CRACK`, `TWIG_SAG`, `CRACK`, `TYPE.twig`, ветку отрисовки «половинки» в `drawPlats`, звук `snap`.

**Вид (`Art.leafPlat`, семя и вариант `v` как у других платформ)**

- Крупный сухой лист лежит плашмя, виден чуть сверху: длина = ширина платформы (66), видимая толщина 9–11. На одном конце острый кончик, на другом короткий загнутый черешок. Сторона черешка зависит от `v`.
- Оба конца приподняты на 2–3 единицы, края слегка волнистые и подвёрнутые. Именно завитые концы читаются как «лёгкий, сухой, ненадёжный».
- Центральная жилка и 4–6 боковых — тонкие вырезанные линии разной длины. На краю одна неровная выемка или дырочка (форма зависит от `v`). 2–3 бледных ржавых крапины.
- Изнанка видна узкой тёмной полоской снизу, как тёмный низ у других платформ.
- Палитра лунного сухого листа в гамме мира: основа `#c9c0d8`, светлая сторона `#ebe6f3`, тёмная и изнанка `#8c84a6`, жилки `#6d6590`, крапины `#a8909a`. Тёплый коричневый не бери: он спорил бы со светлячками.
- Правила рисования — как для всего живого (раздел 10.2): контур из вручную расставленных точек, не симметричный.

**Поведение**

- Приземление (`land`): герой отталкивается как от кочки. Лист сразу срывается (`pl.fall = 1`), статистика и задание считаются как сейчас.
- Падение (`stepPlats`): планирует, как настоящий лист. Фаза φ растёт на 3,2 рад/с. Смещение по x = A·sin φ, A = 18–26. Наклон = 0,5·cos φ (лист кренится в сторону движения). Скорость падения 70 + 40·|cos φ| ед/с: внизу качания быстрее. Исчезает за 1,6 с. Старая гравитация и `pl.vy` у листа не нужны.
- Отрисовка падения (`drawPlats`): спрайт листа со сдвигом и поворотом вокруг середины, без разделения.
- Частицы: 3–4 крошечные крошки цветов листа (размер 2–2,6, падают), а не щепки.
- Звук `Snd.fx.rustle` вместо `snap`: сухой шорох (два коротких всплеска шума в полосе 3–5 кГц, по 60–90 мс) и мягкое «тук» (180 → 120 Гц). Вместе с ним, как сейчас, звучит обычный `bounce`.
- Пыль при приземлении (`DUST.puff`) — цвет основы листа.

**Генерация:** ширина `puff` 60 → 66. Правило «рядом всегда обычная кочка» остаётся. Тексты задания и памятки — раздел 12.

## 9. Монстры: пять видов ворчунов

Вместо одного ворчуна — пять видов, у каждой зоны свой, и все движутся по-разному. Общее имя для всех остаётся «ворчуны», поэтому задание «Приземлись сверху на N ворчунов» и статистика «Сбито ворчунов» не меняются и считают всех.

| Вид (`kind`) | С какой высоты | Как движется | Как победить | Чем опасен |
| --- | --- | --- | --- | --- |
| Репейник (`burr`) | 900 м, все зоны | Качается из стороны в сторону, как нынешний ворчун | Прыжок сверху | Касание сбоку или снизу сталкивает вниз |
| Паук (`spider`) | 1 100 м | Висит на нитке, медленно поднимается и опускается | Прыжок сверху рвёт нитку | Касание тела; нитка безопасна |
| Жук-сторож (`beetle`) | 1 700 м | Ходит по своей кочке от края до края | Прыжок сверху | Бодает, если коснуться сбоку |
| Сыч (`owl`) | 3 000 м | Сидит у края экрана; глаза вспыхнули — пикирует дугой через экран и улетает | Прыжок сверху во время пике, награда вдвое | Касание во время пике; сидящий безопасен |
| Звёздная медуза (`jelly`) | 5 000 м | Медленно плывёт, колокол пульсирует | Не побеждается: прыжок на колокол подбрасывает на VJ·1,75 | Щупальца и бок колокола жалят |

**9.1. Общие правила** (как у нынешнего ворчуна в `stepWorld`)

- Данные: `game.grumps` → `game.beasts`, запись `{kind, x, y, t, ph, dead, …}` с полями своего вида. `drawGrumps` → `drawBeasts`, в `STAGES` и `__tl` тоже.
- Точка героя для столкновений — как сейчас: `bx = P.x`, `by = P.y + 20`; по x всегда через `wdx` (края экрана склеены).
- **В полёте** (одуванчик, комета) любой ворчун побеждён при касании.
- **Сверху:** `P.vy < 0` и ноги героя `P.y` выше середины существа минус 4. Итог: ворчун побеждён, `P.vy = VJ·1,08`, `flow += 2`, +3×множитель светлячков с надписью `+N`, `stats.stomps++`, `addSum('stomps', 1)`.
- **Иначе:** если `P.inv > 0` — ничего. Если есть пузырь — пузырь лопается, ворчун побеждён, `P.inv = 0,8`. Иначе героя сталкивает: `P.vy = min(P.vy, −420)`, `P.inv = 1,1`, `flow = 0`, звук `hit`.
- У каждого вида своя форма столкновения и своя анимация поражения (ниже), а не общий взрыв треугольников.
- Рисунок по правилам раздела 10.2: авторские контуры, асимметрия, своё лицо, без румянца. Характер — сердитый, но не страшный: игра спокойная. Спрайты кэшируй по кадрам анимации, где это возможно.
- В дзене ворчунов нет, как сейчас.

**9.2. Кто где появляется.** Частота остаётся нынешней (`genStep`: с 900 м, промежуток `lerp(700, 300, d)`, шанс `lerp(0.1, 0.26, d)`). Меняется только выбор вида — по весам зоны:

| Зона | Репейник | Паук | Жук | Сыч | Медуза |
| --- | --- | --- | --- | --- | --- |
| Папоротниковая чаща, 900–1 600 м | 0,65 | 0,35 (с 1 100 м) | — | — | — |
| Кристальные своды, 1 600–3 000 м | 0,30 | 0,25 | 0,45 (с 1 700 м) | — | — |
| Лунные кроны, 3 000–5 000 м | 0,25 | 0,15 | 0,20 | 0,40 | — |
| Звёздная высь, от 5 000 м | 0,20 | — | 0,10 | 0,30 | 0,40 |

- На экране не больше одного сыча: если живой уже есть, вместо нового будет репейник.
- Жуку нужна кочка-хозяйка: опорная платформа этого шага типа `static` шириной не меньше 72. Если такой нет — вместо жука репейник.
- Каждого ворчуна убирай из памяти, когда он ниже камеры (как сейчас). Жука — также вместе с его кочкой.

**9.3. Репейник (`burr`)** — замена нынешнего ворчуна-звезды.

- Вид: круглая головка репейника около 34 ед. Венец из 16–22 колючек разной длины (5–9), каждая с крючочком, крючки загнуты в одну сторону. Тело сливово-бурое `#5b3f5e`, верх `#7e5a7c`, низ `#3b2840`. К боку прилип сухой листик `#a89a7a`.
- Лицо: два узких сердитых глаза-щелочки `#ffd9a8` под колючками, загнутыми вниз, как брови. Маленький надутый рот. Глаза следят за героем по x, как сейчас.
- Движение и столкновение — как у нынешнего ворчуна: качание по x, покачивание ±0,18 рад, круг радиусом 31.
- Поражение: распадается на 3 пучка колючек и 5–6 семян, они падают и гаснут за 0,6 с. Звук `stomp`.

**9.4. Паук (`spider`)**

- Движение: точка крепления нитки на 180–240 ед. выше тела. Тело: y = y0 + A·sin(t·ω + φ), A = 45–80, ω = 0,8–1,3. Лёгкий маятник по x ±5. x выбирай между 60 и 340.
- Вид: пушистое брюшко около 18 ед., тёмно-грифельное `#2e3150`, с узором из 4 неровных светлых пятен `#c9cff0` (намёк на крестовика). Маленькая голова: 2 крупных и 2 мелких глаза, у каждого не больше одной точки-блика. 8 тонких лап с суставами, каждая пара под своим углом, лапы чуть подёргиваются.
- Нитка: тонкая линия `#c9d0ff` с прозрачностью 0,55 от точки крепления до тела, на ней 2–3 крошечные капли росы. Нитка видна заранее, по ней понятно, где ходит паук. Она безопасна.
- Столкновение: круг радиусом 22 вокруг тела.
- Поражение: нитка рвётся и быстро утягивается вверх, паук поджимает лапы и падает, кувыркаясь. Звук `snapThread`: короткий высокий щелчок около 2,8 кГц и мягкий щипок струны.

**9.5. Жук-сторож (`beetle`)**

- Движение: живёт на своей кочке (`host` = id платформы). Положение вдоль кочки u ∈ [−(w/2 − 10), w/2 − 10], скорость 30–50 ед/с. У края пауза 0,4 с, разворот (спрайт отражается), дальше. Стоит на верху кочки и проседает вместе с ней (`pl.sq`).
- Вид: купольный панцирь около 30×18 из 4–5 неровных кристальных граней (`#7fd6e8`, светлая `#d2f6ff`, тёмная `#3f8fae`). Тёмное тело `#1d2440` под ним. Шесть коротких лап в походке «треножником» (2 кадра). Маленькая голова с двумя изогнутыми усиками и крошечными жвалами, глаза-точки.
- Столкновение: эллипс 22×14 по центру панциря.
- Поражение: переворачивается на спину (лапки дрыгают) и, крутясь, падает с кочки. Звук `shell`: два сухих щелчка на 1,6 и 2,2 кГц.

**9.6. Сыч (`owl`)** — состояния: сидит → предупреждает → пикирует → улетел.

- Сидит на коротком сучке, торчащем из левого или правого края экрана, на 60–140 ед. выше опорной кочки. Сидящий безопасен, столкновений нет.
- Предупреждение начинается, когда сыч на экране и герой ниже него не больше чем на 320 ед. 0,8 с: сыч пригибается, глаза раскрываются и вспыхивают лимонным. Звук `hoot`: две мягкие ноты 520 и 430 Гц по 0,18 с с паузой 0,08 с.
- Пике 1,2 с по квадратичной кривой: от сучка через точку прицела к выходу за противоположным краем (x за краем на 30 ед., y = прицел − 60). Прицел — положение героя в начале предупреждения плюс `P.vy·0,25` по y. Скорость плавно нарастает и спадает. Крылья расправлены.
- Столкновение: круг радиусом 24, только во время пике. Прыжок сверху даёт +6×множитель, сыч кувыркается вниз, летят 2–3 пера.
- Вид: маленький плотный сыч с плоской головой и белыми «бровями» галочкой. Крупные лимонные глаза `#f2d64b` с чёрными зрачками, тёмно-буро-серое тело `#5a5560` в белых крапинах (10–14, расставлены вручную), короткий хвост, полосатые маховые. Не должен походить на облик совёнка-сипухи: другое лицо (без «сердечка»), тёмный цвет, жёлтые глаза.

**9.7. Звёздная медуза (`jelly`)**

- Движение: x = x0 + 36·sin(0,45·t). Раз в 1,6 с колокол сжимается, и медуза поднимается на 10 ед. за 0,4 с, потом медленно опускается.
- Вид: колокол около 38×24, полупрозрачный (`#8fb6ff`, 0,28). Кромка `#d2e4ff` (0,85) — неровно вырезанная линия, снизу мелкие фестоны. Внутри 4–6 крапин-«звёздочек»: неровные ромбики 2–3 ед. (`#ffffff`, `#ffe9b0`), а не пятиконечные звёзды. 5 щупалец разной длины (28–44), сужающиеся, `#b9c8ff` (0,6), волной с разной фазой.
- Колокол — круг радиусом 24 у его середины. Сверху: супер-прыжок `P.vy = VJ·1,75`, `flow += 2`, +3×множитель, засчитывается как сбитый ворчун. Медуза резко сжимается, тускнеет и уплывает вниз, исчезая за 1,5 с; дважды на неё не прыгнешь. Звук `jellyBoing`: восходящее скольжение по пентатонике.
- Жало: бок колокола и прямоугольник щупалец (x ± 18, от низа колокола на 40 вниз) действуют как удар ворчуна. Звук `sting`: короткое жужжание (пила 300 Гц, 60 мс, с шумом).
- Полёт кометы или одуванчика рассыпает медузу крапинами, как других ворчунов.

**9.8. Звуки.** Новые `Snd.fx`: `snapThread`, `shell`, `hoot`, `jellyBoing`, `sting`. Громкость на уровне нынешних `stomp` и `hit`, всё синтезом из `tone`/`hiss`. Добавь их в `selfTest`.

## 10. Облики: 12 новых со встроенными следами

Вместо 14 обликов и 8 отдельных следов — 12 обликов, у каждого свой силуэт, лицо, взмах и встроенный след. Вкладка «Следы» исчезает. За удалённые облики и следы игроку возвращаются светлячки. Это главная часть ТЗ: времени на неё не жалей.

**10.1. Почему старые облики выглядят как ИИ** (по коду `Art.char` и снимкам)

- **Один шаблон.** 9 из 14 обликов — одно и то же круглое тело (`SEG.blob`). У всех, кроме мотылька, одинаковые крылышки феи, даже у лягуха и кота. Отличается только «шапка» сверху (`top`).
- **Одно лицо.** Глаза-овалы с радужкой и двумя бликами (`pupil`) и розовые овалы румянца (`cheeks`) у большинства. Это главный штамп ИИ-«милоты» и стоковых картинок.
- **Чистая геометрия.** Всё из `ellipse`, `arc` и треугольников: уши — треугольники, хвост кота — толстая линия. Левая половина зеркалит правую (`for (const s of [-1, 1])`). Дрожание контура `amp = 0.75` при теле шириной 40 глазу не видно.
- **Одинаковая подача.** У каждого тот же блик-пятно слева сверху (`SP.hi`) и та же тень-серп справа снизу (`SHADE`).
- **Пастель.** Почти все сиренево-голубые и часть полупрозрачные, поэтому сливаются с лесом и друг с другом.
- **Нет фактуры и характера.** Ни шерсти, ни перьев, ни позы, ни поворота головы.

Силуэты всех 14 старых обликов (сняты скриптом из Приложения В): одно и то же тело с одними и теми же крылышками, отличается только верх. Новые 12 должны пройти тот же тест и различаться с первого взгляда.

*Здесь в доке картинка, в файл она не попала: силуэты 14 старых обликов, залитые чёрным, — у всех одно и то же тело и крылышки. Её можно пересоздать скриптом из приложения В (лист `silhouettes`).*

**10.2. Как рисовать**

1. **Силуэт прежде всего.** Облик узнаётся по чёрной заливке в игровом размере (около 40 ед., на айфоне около 120 px). 12 силуэтов в ряд не путаются. Общего тела нет: у каждого свои пропорции и поза.
2. **Поворот 3/4.** Голова и мордочка повёрнуты на 15–25°. Облик смотрит туда, куда летит: при смене направления отражается по горизонтали с плавным переходом за 0,1 с (`P.face` от 1 к −1 через 0). В лавке, меню и на иконке смотрит вправо.
3. **Техника «бумажная аппликация».** Облик собран из 4–10 «кусочков бумаги». Каждый кусочек — контур из 12–60 вручную расставленных точек: строка пути SVG → `new Path2D(…)`, кэш на облик. Верхний кусочек отбрасывает жёсткую тень: тот же контур со сдвигом (+0,8; +1,0) тоном темнее, как тень под кнопками интерфейса. Без обводок и градиентов.
4. **Края «ножницами».** В основном плавные кривые, местами прямые срезы и мелкие надрезы. Неровность видна в игровом размере (0,6–1,2 ед. на теле в 40 ед.), но заложена в контур, а не случайным шумом каждый кадр.
5. **`ellipse` и `arc` — только для зрачков и точек меньше 3 ед.** Всё остальное — авторские контуры.
6. **Фактура надрезами.** Мех — зубчики по краю, иголки — неровная гребёнка, перья — фестоны. Пятна и узоры — отдельные кусочки разной формы, а не одинаковые кружки.
7. **Не меньше двух осознанных асимметрий** на облик: наклон головы, загнутое ухо, хвост в одну сторону, неравные пятна.
8. **Лица разные, румянца нет.** Блик в глазу — не больше одной маленькой точки, у части обликов его нет совсем. Веки при моргании по форме глаза вида.
9. **Цвет «под луной».** 2 основных тона + 1 акцент + тени. Тени темнее на 15–25% и сдвинуты к сине-фиолетовому (смешай с `#1a1640` на 0,25). Белый — не `#fff`, а `#ecebe6` или `#eeeef2`. Насыщенность на 10–20% ниже дневной, без неона. Тёплый контрастный герой на холодном лесу читается сразу — это и есть «подходит игре».
10. **Тёмные облики** (Сорока, Летучая мышка, Светлячок) получают холодную кромку — узкий светлый кусочек по верхне-левому краю (`#4a4f74`…`#6f6a8c`), чтобы не теряться на тёмном небе. Мягкий ореол за героем (`drawPlayerAt`, `Art.glow(sk.glow)` 0,14) остаётся, его цвет — поле `glow` облика.
11. **Размер.** Ноги в (0, 0), тело в пределах x ∈ [−22; 22], y ∈ [−44; 0]. Уши, хвосты, кисточки — до y = −60 и x = ±32. Физика не меняется.
12. **Параметры рисования** — те же, что сейчас передаёт `drawPlayerAt`: `t`, `blink`, `lx`/`ly` (куда смотрит), `ear` (вертикальная скорость), `wing` (готовность взмаха 0…1), `flap` (1 → 0 после взмаха), и новый `face`. Внешний вызов остаётся `Art.char(c, sk, a)`, внутри него у каждого облика своя функция `SKIN_ART[id](c, a)`. Старые `SEG`, `GEM`, `SHADE`, `bodyPts`, `skinPal` и поля `shape`, `top`, `eyes`, `cheeks`, `feet` удали.
13. **Каждому облику — одно своё движение в покое** (см. 10.4) сверх общего сжатия и наклона, которые уже делает `drawPlayerAt`.

**10.8. Миграция сохранений**

Схема становится `v: 2`: в `freshSave` — `v: 2`, `skin: 'ezhik'`, `skins: ['ezhik']`, новое поле `refund: 0`, без `trail` и `trails`. Старое сохранение проходит через `migrateV1` в начале `applySave`, до проверки id. Лис и совёнок сохраняют id, грибок становится мухомором. За остальные купленные облики и все следы игрок получает обратно полную цену. За комету и хранителя возврата нет: они были наградами, и их заменят рысь и светлячок по тем же условиям.

```js
const OLD_SKIN_PRICE = { kaplya: 300, lyagukh: 500, kot: 750, zayka: 1700, zhele: 2100, motyl: 2600, kristall: 3200, zvezda: 3900 };
const OLD_TRAIL_PRICE = { sparks: 100, pollen: 200, bubbles: 350, petals: 550, notes: 800, stardust: 1200, aurora: 1800 };
const SKIN_MAP = { gribok: 'mukhomor', lis: 'lis', sova: 'sova' };
function migrateV1(d) {           // старое сохранение: новые облики, светлячки за убранные облики и следы
  if (!d || typeof d !== 'object' || d.v >= 2) return d;
  const skins = Array.isArray(d.skins) ? d.skins : [], trails = Array.isArray(d.trails) ? d.trails : [];
  let refund = 0;
  for (const id of new Set(skins)) refund += OLD_SKIN_PRICE[id] || 0;
  for (const id of new Set(trails)) refund += OLD_TRAIL_PRICE[id] || 0;
  d.skins = ['ezhik', ...skins.map((id) => SKIN_MAP[id]).filter(Boolean)];
  d.skin = SKIN_MAP[d.skin] || 'ezhik';
  d.coins = (typeof d.coins === 'number' ? d.coins : 0) + refund;   // totalCoins не трогаем: это не собрано в лесу
  d.refund = refund;
  delete d.trail; delete d.trails;
  d.v = 2;
  return d;
}
```

- После загрузки в меню: если `save.refund > 0`, тост «Облики обновились: вернули светлячков за прежние облики и следы» с суммой. Потом `save.refund = 0` и `persist()`. Повторная загрузка не начисляет второй раз.
- Сразу после загрузки вызови `checkUnlocks(0)`: те, у кого рекорд уже не меньше 3 000 м или 12 заданий, сразу получат рысь и светлячка.
- `importCode`: принимает `v` 1 и 2 (префикс остаётся `TL1.`). `exportCode` пишет `v: 2` с тем же префиксом. Ключ `localStorage` не меняется.
- «Сбросить прогресс» даёт чистое сохранение v2 и, как сейчас, сохраняет настройки и отметку подарка.

## 13. Проверка

Каждый этап проверяется автотестами в браузере и листами снимков, которые ты сам открываешь и смотришь. Облики и ворчуны ещё проходят чек-лист и свежий взгляд. «Код работает» — не доказательство: главный риск этого обновления в том, что картинка снова выйдет похожей на ИИ.

**13.1. Среда.** Playwright (Python или Node) и Chromium. Окно iPhone 16 Pro Max: 440×956, `deviceScaleFactor` 3, `isMobile`, `hasTouch`. Игру раздавай по http (`python3 -m http.server`), иначе не заработает service worker. Скрипт-основа — Приложение В. После каждого запуска в консоли должно быть ноль ошибок.

**13.2. Автопроверки**

1. Пустое сохранение: меню без ошибок, надет Ёжик, кнопка подарка видна.
2. Подарок: нажатие даёт +100, кнопка исчезает, есть тост. Двойное нажатие даёт 100, а не 200. После перезагрузки кнопки нет. С датой +1 день (подмена `Date` через `add_init_script`) кнопка снова есть.
3. Миграция: старое сохранение с обликами `gribok`, `kot`, `zvezda`, следами `sparks`, `aurora`, надет `kot`. После загрузки: `skins` = `ezhik`, `mukhomor`; надет `ezhik`; светлячков больше на 750 + 3 900 + 100 + 1 800 = 6 550; тост о возврате один раз, повторная загрузка больше не начисляет. Код переноса `TL1.` из старого `index.html` (возьми из git) загружается в новую версию. Игрок с рекордом 3 200 м сразу получает рысь.
4. Светлячки: при ×3 на снимке одиночные огоньки, поимка одного даёт +3.
5. Призрачная кочка: форма-капсула на снимке, не держит, тает от касания сверху и при пролёте сквозь.
6. Сухой лист: держит один прыжок, потом падает с покачиванием и исчезает. Рядом есть обычная кочка. Задание `puffs` считает.
7. Ворчуны: сгенерируй лес до 7 000 м с фиксированным `game.seed` и посчитай виды по зонам: доли должны совпадать с таблицей 9.2 с точностью около 0,1. Для каждого вида проверь: прыжок сверху (у медузы — супер-прыжок), касание сбоку, пузырь, полёт кометы. Паук движется в пределах амплитуды, жук не уходит со своей кочки, сыч предупреждает не меньше чем за 0,8 с. В дзене ворчунов нет.
8. Лес проходим: бот с идеальным прицелом доходит до 7 000 м без тупиков (ворчуны не перекрывают единственный путь).
9. Облики: каждый покупается и надевается. 10 с забега на каждом без ошибок. Взмах проигрывает свою анимацию, след вылетает и не превышает 40 частиц. При смене направления облик разворачивается.
10. Скорость: средний кадр в забеге при 4-кратном замедлении процессора (CDP `Emulation.setCPUThrottlingRate`) не хуже версии «до» больше чем на 15%. Проверь с самым тяжёлым следом и в зоне с медузами.
11. «Экономно»: всё рисуется, свечения и ореолов нет.
12. Офлайн: после первой загрузки выключи сервер — игра открывается и играется. В `sw.js` новое имя кэша.

## 14. Выдача и отчёт Андрею

Выдача состоит из четырёх шагов: новое имя кэша в `sw.js`, коммит в `main` (или файлы для ручной загрузки), запись в `ИСТОРИЯ.md` и короткий отчёт по-русски.

1. **Имя кэша.** `tiholesye-` + первые 12 знаков sha256 от файлов игры в алфавитном порядке имён (так же делала старая сборка). Команда из корня репозитория:

```bash
node -e "const fs=require('fs'),h=require('crypto').createHash('sha256');for(const f of ['icon-180.png','icon-192.png','icon-512.png','index.html','manifest.webmanifest'])h.update(f).update(fs.readFileSync(f));const v=h.digest('hex').slice(0,12);fs.writeFileSync('sw.js',fs.readFileSync('sw.js','utf8').replace(/tiholesye-[0-9a-f]{12}/,'tiholesye-'+v));console.log(v)"
```

2. **Список `FILES` в `sw.js`** остаётся прежним. `CLAUDE.md`, `ИСТОРИЯ.md` и `тз/` туда не добавляй.

4. **Запись в `ИСТОРИЯ.md`** по шаблону раздела 4: имя кэша, коммит, «Решено без Андрея», что проверено, что не сделано. Обнови `CLAUDE.md`, если что-то в устройстве изменилось по ходу работы.

| 11.11.2026 — первая версия (v1) | Своя игра для айфона без интернета, например на остановке. Прыгалка вверх в духе Doodle Jump, но полностью своя: без чужих персонажей, графики и названий. Спокойный ночной волшебный лес со светящимися грибами; фиолетовый, синий, голубой; облики; интерфейс по-русски | Один HTML-файл: механики, 5 зон, 14 обликов, 8 следов, 6 усилений, задания и ранги, дзен, звук синтезом | Перегружено. Грибы стали платформами, хотя имелись в виду грибы на фоне |

**Вкус Андрея** — выжимка из его журнала и этого запроса. Перенеси в `CLAUDE.md`:

- Игра не должна выглядеть сделанной нейросетью. Что под капотом, игроку всё равно, но внешне он не должен об этом даже задуматься.
- Минимализм, но не примитив. Перегруженный экран плохо (v1), экран из одних простейших фигур тоже плохо (v2).
- Цвета мира: фиолетовый, синий, голубой, все три видны. Перекос в фиолетовый не нравится.
- Светящиеся грибы — часть леса, фон и украшение. Платформы — мшистые кочки.
- Тёплый светящийся цвет в лесу один — светлячки. С 21.11 облики могут быть тёплыми и контрастными, но «под луной».
- Ничего из Doodle Jump и других игр: ни персонажей, ни названий, ни узнаваемых решений.
- Интерфейс «бумага и чернила» и дизайн кочек v4 ему очень нравятся: без просьбы не трогать.
- Подсказки не должны быть навязчивыми: дорожка «+N» и стайки светлячков ему не понравились.
- Интерфейс и тексты по-русски, с правильными окончаниями у чисел.
- С ним: по-русски, честно, без лести, подробно; команды терминала объяснять по словам.

**Выводы на будущее** (сделаны Claude по ходу работы): просьбу «в лесу есть X» не превращать в «всё из X»; «проще» не значит «из кругов»; знакомый приём из известной игры читается как копия; шаблон «тело + шапка» и одно милое лицо на всех выдают ИИ сильнее всего.

## Приложение В. Скрипт снимков на Playwright

Скрипт проверен на текущей версии игры: снимает меню, лавку, памятку, листы обликов (в цвете, силуэтами и в четырёх состояниях), платформы и пять зон; ошибок в консоли ноль. На листе силуэтов старых обликов сразу видна главная проблема: 14 одинаковых тел с одинаковыми крылышками. После обновления добавь в `SHEET` листы ворчунов, следов и «до/после». Путь к своему Chrome можно передать переменной `CHROME`.

```python
"""Снимки «Тихолесья» для проверки на глаз.

Запуск (из любой папки):
  python3 -m http.server 8765 --bind 127.0.0.1 --directory <папка репозитория>   # в отдельном окне
  python3 shots.py <папка для снимков>
Нужен Playwright: pip install playwright && python3 -m playwright install chromium
Скрипт опирается на window.__tl. Когда появятся новые функции (ворчуны, следы), добавь их в SHEET.
"""
import asyncio, base64, os, sys
from playwright.async_api import async_playwright

URL = 'http://127.0.0.1:8765/index.html'
OUT = sys.argv[1] if len(sys.argv) > 1 else 'shots'
os.makedirs(OUT, exist_ok=True)

# листы рисуются функциями самой игры на большом холсте и возвращаются как PNG
SHEET = r"""({what, scale}) => {
  const T = window.__tl, A = T.Art, cv = document.createElement('canvas'), x = cv.getContext('2d');
  const label = (s, cx, cy, col) => { x.fillStyle = col; x.font = `${10 * scale}px sans-serif`; x.textAlign = 'center'; x.fillText(s, cx, cy); };
  if (what === 'skins' || what === 'silhouettes') {             // все облики в цвете или чёрными силуэтами на белом
    const cols = 6, cw = 110 * scale, ch = 120 * scale, n = T.SKINS.length, dark = what === 'skins';
    cv.width = cw * cols; cv.height = ch * Math.ceil(n / cols);
    x.fillStyle = dark ? '#141a52' : '#ffffff'; x.fillRect(0, 0, cv.width, cv.height);
    T.SKINS.forEach((sk, i) => {
      const c2 = document.createElement('canvas'); c2.width = cw; c2.height = ch; const y = c2.getContext('2d');
      y.translate(cw / 2, ch - 22 * scale); y.scale(scale * 1.2, scale * 1.2); A.char(y, sk, { t: 0.873, wing: 1 });
      if (!dark) { y.setTransform(1, 0, 0, 1, 0, 0); y.globalCompositeOperation = 'source-in'; y.fillStyle = '#000'; y.fillRect(0, 0, cw, ch); }
      const ox = (i % cols) * cw, oy = Math.floor(i / cols) * ch;
      x.drawImage(c2, ox, oy); label(sk.name, ox + cw / 2, oy + ch - 6 * scale, dark ? '#eef0ff' : '#000');
    });
  }
  if (what === 'states') {                                      // каждый облик: покой, моргание, взмах, без заряда
    const S = [['покой', { t: 0.873, wing: 1 }], ['моргает', { t: 0.873, wing: 1, blink: true }], ['взмах', { t: 0.873, wing: 1, flap: 0.6 }], ['без заряда', { t: 0.873, wing: 0 }]];
    const cw = 110 * scale, ch = 110 * scale;
    cv.width = cw * S.length; cv.height = ch * T.SKINS.length; x.fillStyle = '#141a52'; x.fillRect(0, 0, cv.width, cv.height);
    T.SKINS.forEach((sk, r) => S.forEach(([nm, a], k) => {
      x.save(); x.translate(k * cw + cw / 2, r * ch + ch - 22 * scale); x.scale(scale * 1.2, scale * 1.2); A.char(x, sk, a); x.restore();
      label(`${sk.name} · ${nm}`, k * cw + cw / 2, r * ch + ch - 6 * scale, '#eef0ff');
    }));
  }
  if (what === 'plats') {                                       // все платформы крупно
    A.setScale(scale);
    const types = [['static', 84], ['moving', 84], ['bouncy', 72], ['puff', 66], ['fake', 78], ['phase', 78], ['home', 150]];
    const cw = 170 * scale, ch = 80 * scale;
    cv.width = cw * 2; cv.height = ch * Math.ceil(types.length / 2); x.fillStyle = '#1a155e'; x.fillRect(0, 0, cv.width, cv.height);
    types.forEach(([tp, w], i) => {
      const s = A.plat(tp, w, 0, 1), cx = (i % 2) * cw + cw / 2, cy = Math.floor(i / 2) * ch + 22 * scale;
      x.drawImage(s.c, cx - s.ox * scale, cy - s.oy * scale, s.w * scale, s.h * scale); label(tp, cx, cy + 52 * scale, '#eef0ff');
    });
  }
  return cv.toDataURL('image/png');
}"""

# забег в дзене (упасть нельзя), герой переносится на нужную высоту, лес догенерируется
JUMP = r"""(h) => {
  const T = window.__tl, g = T.game, P = T.P, y = g.startY + h * 10;
  for (let k = 0; k < 40 && g.plats.length; k++) T.genUpTo(y + 1500);
  P.y = y; P.vy = 400; T.run.maxY = y; g.camY = y - T.view.H * 0.44;
  for (let k = 0; k < 30; k++) T.update(1 / 60);
  P.y = y + 200; P.vy = 300; g.camY = P.y - T.view.H * 0.44; T.update(1 / 60); T.render();
}"""


async def main():
    async with async_playwright() as p:
        b = await p.chromium.launch(executable_path=os.environ.get('CHROME') or None)
        ctx = await b.new_context(viewport={'width': 440, 'height': 956}, device_scale_factor=3, is_mobile=True, has_touch=True)
        pg = await ctx.new_page()
        errors = []
        pg.on('pageerror', lambda e: errors.append(str(e)))
        pg.on('console', lambda m: m.type == 'error' and errors.append(m.text))
        await pg.goto(URL)
        await pg.wait_for_function('window.__tl && window.__tl.game.state === "menu"')
        await pg.wait_for_timeout(1200)
        shot = lambda name: pg.screenshot(path=os.path.join(OUT, name + '.png'))
        await shot('01-menu')
        await pg.click('#bShop'); await pg.wait_for_timeout(400); await shot('02-shop')
        await pg.click('#shop [data-close]'); await pg.wait_for_timeout(200)
        await pg.click('#bSet'); await pg.wait_for_timeout(200); await pg.click('#bHelp'); await pg.wait_for_timeout(400); await shot('03-help')
        await pg.click('#help [data-close]'); await pg.wait_for_timeout(200); await pg.click('#settings [data-close]'); await pg.wait_for_timeout(200)
        for what in ['skins', 'silhouettes', 'states', 'plats']:
            data = await pg.evaluate(SHEET, {'what': what, 'scale': 3})
            open(os.path.join(OUT, f'10-{what}.png'), 'wb').write(base64.b64decode(data.split(',')[1]))
        await pg.evaluate('() => { const T = window.__tl; T.game.zen = true; T.startRun(true); }')
        await pg.wait_for_timeout(800)
        for h in [350, 1100, 2100, 3600, 5600]:
            await pg.evaluate(JUMP, h); await pg.wait_for_timeout(400); await shot(f'20-run-{h}m')
        print('ошибок в консоли:', len(errors)); [print(' ', e) for e in errors[:20]]
        await b.close()

asyncio.run(main())
```
